# 소설 집필 웹 편집기 — 설계

## 목적과 이유
뮤블의 AI 기능은 포인트가 필요하다. 사용자는 대신 Claude(구독)로 집필 도움을 받고 싶다.
그래서 이 앱에는 AI 기능이 없다. 원고를 구글 드라이브에 저장하고, AI 도움은 데스크톱의 Claude Code 대화창에서 드라이브 파일을 읽어서 받는다.
뮤블의 코드·이름·디자인은 쓰지 않는다(공개된 소스 없음). 기능만 참고한 별개 프로그램이다.

## 기기
- 집 데스크톱, 휴대폰. 둘 다 브라우저에서 같은 주소로 연다.

## 목표
- 작품 목록 → 회차 목록 → 편집기
- 작품마다 설정 메모(인물·세계관) 한 개
- 글자 수(공백 포함 / 제외)
- 자동 저장(입력 멈춘 뒤 2초, 화면을 벗어날 때)
- 휴대폰 화면에서도 편하게 쓸 수 있는 배치

## 하지 않는 것
- 앱 안의 AI 기능(API 요금 발생)
- 오프라인 작성(나중에 필요하면 2번 방식으로 추가)
- 굵게·기울임 같은 서식, 내보내기, 여러 사람 공동 작업

## 절대 안 되는 것
- 글이 말없이 사라지거나 덮어써지는 것

## 고려한 방법
1. **웹페이지 하나 + 구글 드라이브 직접 저장** ← 선택. 코드가 가장 작고 모든 기기에서 된다.
2. 1번 + 설치형 앱/오프라인 — 충돌 처리 코드가 많아져서 보류.
3. 구글 문서만 사용 — 코드는 없지만 집필 전용 화면이 없음.

## 만드는 방법
- 파일: `index.html`, `app.js`, `style.css`. 빌드 도구나 프레임워크 없이 만든다.
- 호스팅: GitHub Pages(무료, https).
- 로그인: Google Identity Services(브라우저 토큰 방식). 사용자가 만든 구글 클라우드 프로젝트의 클라이언트 ID를 `app.js` 맨 위에 적는다.
- 권한: `drive.file`(이 앱이 만든 파일만 볼 수 있다). *내가 정함:* 드라이브 전체 권한보다 안전하기 때문이다. 대신 앱 밖에서 새로 만든 파일은 앱에 안 보인다. 그래서 Claude는 새 파일을 만들지 않고, 앱이 만든 파일을 고치거나 대화창에 글을 제안한다.
- 드라이브 구조:
  ```
  내소설/
    <작품 제목>/
      설정.md
      001 - <회차 제목>.md
      002 - <회차 제목>.md
  ```
  일반 텍스트(.md)로 저장해서 Claude와 사람 모두 그대로 읽을 수 있다. 회차 순서는 파일 이름 앞의 번호로 정한다.
- 충돌 방지: 파일을 열 때 드라이브의 수정 시각을 기억해 둔다. 저장하기 직전에 다시 확인해서 그사이 다른 기기에서 바뀌었으면 덮어쓰지 않는다. 지금 쓴 글은 `001 - 제목 (충돌 2026-11-10 21-30).md`로 따로 저장하고 알림을 띄운다.
- 저장 실패(인터넷 끊김, 로그인 만료): 화면에 "저장 안 됨"을 보여 주고, 글을 브라우저에 임시로 보관한 뒤 다시 시도한다.
- 로그인은 약 1시간 뒤 만료될 수 있다. 그때는 다시 로그인 버튼을 띄운다. *한계로 받아들임.*

## 사용자가 할 일(안내 제공)
- GitHub 계정 만들기
- 구글 클라우드 콘솔에서 프로젝트와 OAuth 클라이언트 ID 만들기, 본인을 테스트 사용자로 등록
  (로그인할 때 "확인되지 않은 앱" 경고가 뜨는데, 본인 앱이라 괜찮다)

## 만드는 사람에게 맡김
- 화면 디자인 세부, 회차 이름 바꾸기·삭제(삭제는 드라이브 휴지통으로)
- 충돌 판단 로직과 파일 이름 규칙은 작은 자체 테스트로 확인한다
